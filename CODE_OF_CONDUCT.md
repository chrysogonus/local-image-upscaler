# Code of conduct

## The standard

This project exists to make a technical thing work well. Everyone taking part —
in issues, pull requests, and reviews — is expected to keep it a place where
that is possible:

- Assume the other person is trying to make the software better.
- Criticise the change, not the person who wrote it. "This resamples where it
  claims to reconstruct" is review. "You clearly don't understand this" is not.
- Accept that a change can be well made and still be declined on scope. Say why,
  and move on.
- Harassment, insults, discriminatory language, personal or political attacks,
  publishing anyone's private information, and unwelcome sexual attention are
  not tolerated in any project space.

"Project space" means anything under this repository — issues, pull requests,
discussions, commit messages, code, and review comments — and any place someone
is representing the project.

## Enforcement

The maintainer may edit, hide, or delete comments, commits, and issues that
break this standard, and may block an account from the repository. Severity and
repetition decide which.

## Reporting

Report a concern privately through either:

- **GitHub's report-abuse flow**, from the "..." menu on the comment or account
  in question. This reaches GitHub directly and is the right route for anything
  that also breaks GitHub's own terms.
- **A private security advisory** on this repository, which is a private channel
  to the maintainer even though the form is written for vulnerabilities. Say in
  the first line that it is a conduct report, not a security one.

This project deliberately publishes no personal email address, which is why
neither route is an inbox. Both are private: nothing you send is visible to the
person you are reporting, or to anyone else.

Every report is read. The maintainer will not discuss a report publicly, or
confirm that one exists, and will not disclose who made it.

## Scope and honesty about what this is

This is a single-maintainer project, so there is no committee, no appeals
process, and no promised response time — claiming otherwise would be the kind of
overstatement [`AGENTS.md`](AGENTS.md) argues against everywhere else. What is
promised is that reports are read and acted on, and that the standard above
applies to the maintainer too.
